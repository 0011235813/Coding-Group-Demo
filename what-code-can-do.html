Water Coding Group · Show & Tell

What code can do with our data.

Every panel below is running live in this browser. No server, no install. Right click, view source, and you can read exactly how each one works. The same building blocks power our Shiny apps and dashboards.

We spend a lot of time getting data clean and correct. This is the other half: turning it into something a person can read, click, and reason about. Charts, maps, calculators, tables, and simulations are all just code, and most of it is less code than you would think. Scroll through, poke at everything, and steal whatever is useful.

01 Interactive charts

A hydrograph you can talk to

Static plots answer one question. Interactive ones let the audience ask their own. Toggle parameters on and off, hover for exact values. This is a few lines of Chart.js on a simple data frame.

Under the hood: one dataset, one canvas element, a JSON options object. In R this is the same idea as plotly or dygraphs inside a Shiny app.
02 Reactive inputs

Move a slider, watch the lake change

This is reactivity, the thing that makes Shiny feel alive. Three inputs feed a Carlson Trophic State Index calculation, and the result redraws the lake and its class instantly. No submit button, no reload.

03 Spatial & maps

Put the stations on a map

Coordinates in a table are hard to read. On a slippy map they tell a story. Click a marker for its record. Color encodes trophic status. This is Leaflet, the same library behind the GMAP groundwater dashboard.

Under the hood: a list of points, a base map, one loop that drops a colored circle per site. Popups are just HTML strings.
04 Data & tables

Tables that sort, search, and flag

A results export does not have to be a wall of numbers. Click any header to sort. Type to filter. Values over the criterion light up on their own. This is the QA reviewer's best friend.

Under the hood: sort compares one column, filter hides rows that do not match, the flag is a simple rule per parameter. DT and reactable do this in R with almost no code.
05 Simulation & animation

A contaminant plume, particle by particle

Code can also model process, not just display data. Here a source releases particles that drift downstream and spread out, advection plus diffusion. Click anywhere on the water to add a new source. Change the current and mixing and watch the plume respond.

Under the hood: a few hundred particles, each nudged by the current plus a random step every frame. Simple rules, complex-looking result. The same loop drives game engines and weather toys.
06 Just because it is fun

Touch the water

Not everything has to be a deliverable. Code responds to people. Click or drag across the surface and it ripples. Good interfaces feel like this even when the subject is a lab result.

Under the hood: each click spawns an expanding ring, the animation loop fades them out. Pure event handling and a redraw. This is the whole trick behind interfaces that feel responsive.

All of this is the same toolbox

Charts, maps, reactive inputs, tables, and simulations are not six separate skills. They are the same loop: take data, respond to a person, redraw. Learn it once in the browser and it carries straight into Shiny, into R Markdown, into the apps we ship.
